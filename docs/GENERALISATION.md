A single accuracy figure is not a claim anyone can check. This document reports four,

**This document is written whatever the numbers are.** A generalisation report that

inflate a score: with few siblings per capture there is little to leak, and the random
split below is correspondingly weak as a test.

## Interpretation

The random split scores +0.2% against the capture split — the **inflation a leaking split buys on this dataset**, measured rather than assumed.

**That small gap is not evidence that leakage is harmless, and must not be read as one.** This dataset averages 2.31 windows per capture, so a random split has very few sibling windows available to leak — the test has little power here. Leakage scales with windows per capture: before the protocol-50 artefacts were removed, one traffic class averaged 29.4 windows per capture, and a random split over that data would have leaked heavily. The grouped split is cheap insurance whose value does not show up in this particular number.

Accuracy is essentially unchanged (+1.7%) between held-out captures and held-out configurations. The model is reading traffic shape rather than configuration, which is the intended result — and it is worth stating that the corpus has 7 traffic classes generated by deliberately distinct tools, so the classes are more separable here than arbitrary real-world traffic would be.

On unseen Diffie-Hellman groups accuracy is **96.7%** (-0.3% against the capture split). The model is not leaning on a key-exchange artifact, which is what the corpus was balanced to make testable.

## Limitations

* The corpus has seven traffic classes produced by deliberately distinct generators, so
  the classes are more separable than arbitrary real-world traffic. These numbers are an
  upper bound on what the same approach would achieve on a production estate.
* All cells are tunnel mode; mode inference cannot be evaluated here at all. See
  `docs/BASELINES.md`.
* Sample size is modest. Differences of a few percent between splits are within noise.
