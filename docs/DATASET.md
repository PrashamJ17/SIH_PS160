# Dataset: methodology, provenance and limitations

This document exists because the corpus is the part of this project most likely to be
wrong in ways that are invisible from the outside. It states what was generated, how
the labels were obtained, what stands in for something it is not, and where the data
should not be trusted.

Everything asserted here is either reproducible with a command in this repository or
recorded as a limitation. Nothing is claimed that a reader cannot check.

---

## 1. Why we generated our own data

The problem statement points at CIC-IDS2017, CSE-CIC-IDS2018, UNSW-NB15, CTU-13,
CICIoT2023, LANL and DARPA. Every one of them was built for **intrusion detection**,
not protocol analysis, and none contains the traffic an IPsec analyser needs:

* no **IKE negotiations** (UDP 500, or UDP 4500 with the non-ESP marker),
* no **ESP** (IP protocol 50) or **AH** (IP protocol 51),
* and therefore no label for cipher, integrity algorithm, DH group, tunnel-versus-
  transport mode or PFS — those values exist only *inside* a negotiation.

We did not take this on trust from the literature. **[`docs/external_dataset_audit.md`](external_dataset_audit.md)**
is generated by `scripts/audit_external_datasets.py`, which walks every capture present
and counts those three things without sampling.

That audit carries a **positive control**, and the control is the point rather than a
formality: a script reporting zero IPsec packets proves nothing until it is shown to
find IPsec when IPsec *is* there. Each run therefore scans this project's own captures
first and requires both an IKE-bearing and an ESP-bearing result — ESP alone would pass
a scanner that was blind to handshakes. A run whose control fails writes a report marked
**INVALID**, states that its zeros must not be cited, and exits non-zero.

That guard has already fired for real. The first run's control found ESP but no IKE,
because the captures it happened to select were taken *after* the tunnel was
established. The audit refused to report until the control genuinely passed.

**Reproduce it:**

```bash
python scripts/audit_external_datasets.py
```

### The conclusion that follows

No public corpus supplies IPsec crypto labels. Even a capture that did contain ESP
would carry no record of what was negotiated, so it could not train or evaluate the
identification this problem asks for. Generating the corpus is therefore **objective
(a)**, not a workaround for it.

## 2. How the named datasets *are* used

They are used, and the use is deliberate rather than face-saving.

Their benign traffic is **real** traffic — real applications, real packet sizes, real
burst structure. `testbed/traffic/replay.py` replays it through our tunnels as **inner
payload**, so the corpus gets authentic traffic shape while our own configuration
supplies the crypto labels. Source and destination addresses and MACs are rewritten so
the frames route through the gateway; nothing else about them is altered.

This is the only technically sound use of those corpora for this problem. It is worth
saying plainly to anyone who asks why we "did not use the datasets": we did, as
payload, because payload is the only thing in them this problem can use.

**Limitation.** Replay preserves packet sizes faithfully but **distorts inter-arrival
timing** according to the replay rate. Timing-derived features from replayed cells are
therefore less trustworthy than size-derived ones, and the `replay` class should be read
as "background traffic of realistic shape", not as a faithful reproduction of the
original capture's dynamics.

## 3. Known limitations of ISCXVPN2016

ISCXVPN2016 is the closest public VPN corpus, and it is still not usable as an IPsec
reference:

* Its "VPN" captures are **OpenVPN**, not IPsec. Packet-size features do not transfer:
  ESP padding, tunnel-mode encapsulation overhead and block-cipher padding all change
  the size distribution.
* It carries **no crypto parameter labels** of any kind.
* It has documented quality problems. Aceto et al.'s DISTILLER analysis (2021) reports
  that roughly 65% of its biflows consist of a single UDP packet to
  `255.255.255.255:10505` — BlueStacks broadcasts emitted every two seconds — and later
  work notes a large fraction of some captures is not encrypted at all. It requires
  cleaning before any use.

We therefore treat it as a comparison baseline for traffic classification only, never
as IPsec ground truth.

## 4. Generation methodology

### Configuration matrix

`testbed/configs/matrix.yaml` defines the space; `testbed/orchestrate/matrix.py`
samples **36 distinct configurations** from it. A full factorial would be 576 cells
before traffic and impairment multiply it, which buys coverage of the product space
rather than of the security-relevant spread.

| Dimension | Values |
|---|---|
| IKE version | IKEv1, IKEv2 |
| Encryption | aes256gcm16, aes128gcm16, aes256, aes128, 3des |
| Integrity | sha256, sha384, sha1, md5 (AEAD ciphers carry none) |
| DH group | modp1024, modp1536, modp2048, ecp256, ecp384, curve25519 |
| PFS | on, off |
| Mode | tunnel, transport |
| Lifetimes | IKE 4/8/24 h, child 30 min / 1 h / 8 h |

Five **anchor configurations** are always present, so the security-relevant extremes
are never sampled away:

| Anchor | Configuration |
|---|---|
| `worst` | IKEv1 Aggressive Mode, 3DES, MD5, DH group 2, PFS off |
| `weak` | AES-128, SHA-1, DH group 2, PFS off |
| `medium` | AES-128, SHA-256, DH group 14, PFS on |
| `good` | AES-256, SHA-384, DH group 20, PFS on |
| `best` | AES-256-GCM, Curve25519, PFS on |

### Balance — the confound guard

Sampling is not left to chance on the axis that matters most. Expansion **guarantees**
that every DH group appears, and that **every encryption algorithm appears with at
least two different DH groups**; the realised spread is 3–6 groups per cipher. The
sweep planner enforces the stronger property before anything runs: **every generator
must meet every encryption algorithm**, and a plan that would not is rejected outright.

This is the guard against the most fatal trap available here. If VoIP only ever rode
AES-GCM and video only AES-CBC, an "application classifier" trained on the result would
really be a cipher detector, and no downstream care would recover from it.

### Traffic classes

Seven classes, driven against real servers wherever a real server exists:

| Class | Driven by | Variants |
|---|---|---|
| `icmp` | `ping` | 3 |
| `voip` | synthetic RTP endpoints (see §6) | 2 |
| `video` | self-hosted nginx origin, DASH-style segment player | 3 |
| `web` | self-hosted nginx corpus, scripted browser with think time | 2 |
| `email` | **real Postfix and Dovecot**, driven by `smtplib`/`imaplib` | 3 |
| `messaging` | **real Prosody**, driven by `slixmpp` (see §6) | 2 |
| `replay` | `tcpreplay` of an external capture | 2 |

Nothing reaches the public internet: every origin is local, so a sweep is reproducible
and can run air-gapped.

Class separation is measured rather than asserted — `scripts/generator_shapes.py`
reports the features a classifier would see, and the results are in
`reports/generator_shapes.json`.

### Network impairment

Applied to **both** gateways' transit interfaces, because `tc netem` shapes egress
only and impairing one end would leave half of every round trip untouched.

| Profile | Delay | Jitter | Loss | Rate |
|---|---|---|---|---|
| `clean` | — | — | — | — |
| `lan` | 1 ms | — | — | 1000 Mbit |
| `wan_good` | 20 ms | 2 ms | 0.1% | 100 Mbit |
| `wan_poor` | 80 ms | 15 ms | 1.0% | 10 Mbit |
| `satellite` | 300 ms | 30 ms | 2.0% | 5 Mbit |

Without impairment a classifier learns this lab's unnaturally clean network: every
inter-arrival feature is a property of the path as much as of the application.

### Dual-tap capture

Each cell captures twice at once:

* **Outer**, on the transit link, filtered to `udp port 500 or udp port 4500 or
  ip proto 50 or ip proto 51` — what a passive observer sees.
* **Inner**, on the gateway's protected interface, unfiltered — the cleartext, which
  gives every flow a perfect application label.

Two details are load-bearing and easy to get wrong:

1. **Capture starts before the tunnel is initiated.** The IKE handshake happens exactly
   once, during initiation, and it is the entire input to the deterministic parser lane.
   Capturing afterwards yields cells full of ESP with no negotiation to read.
2. **The outer filter is deliberately narrow.** Capturing on a peer sees inbound packets
   twice — once as ESP and once as the decrypted copy the kernel re-injects — so a wider
   filter would put plaintext into the *outer* capture and silently corrupt the corpus.

Traffic is generated between **hosts behind** the gateways, not by the gateways
themselves. A packet a gateway originates never crosses its own protected interface, so
driving from a gateway yields only the inbound half of every conversation and every
directional feature is computed from half a flow.

## 5. Label provenance

**Labels come from reality, never from intent.**

A configuration file records what was *asked for*. Peers negotiate, and what they settle
on is not always the same. Training on intent produces a corpus whose labels are quietly
wrong, and nothing downstream recovers from that.

Every label is therefore read back from **two independent observations**:

| Source | What it gives |
|---|---|
| `swanctl --list-sas` | the daemon's view: negotiated cipher, key length, integrity, PRF, DH group, mode, SPIs, NAT-T state |
| `ip xfrm state` | the kernel's view: the SAs actually installed, their algorithms and replay windows |

Each manifest carries the intent, both observations, and an explicit
**`negotiation_matched_intent`** flag plus a list of exactly how they diverged. A cell
where that flag is false has labels describing something other than what was captured,
and downstream consumers must respect it.

**No key material is ever extracted.** `ip xfrm state` prints session keys inline; the
parser matches them only in order to skip them, records the algorithm name and ICV
length, and never places key bytes in a returned object. Tests assert that no manifest
contains a long hex literal. The one committed kernel fixture had its keys redacted
before it was added.

No credential appears anywhere in this repository. Tunnel PSKs, mailbox passwords and
XMPP account passwords are generated per run and passed through the environment.

## 6. What stands in for something it is not

Two classes are proxies. Both are named here rather than implied away, because a corpus
that overclaims discredits every number computed from it.

### `messaging` is XMPP, not WhatsApp

The messaging class is **genuine XMPP** — a real Prosody server driven by `slixmpp` —
used as a **shape proxy** for consumer messaging.

It is **not** WhatsApp, Signal, or any specific consumer messenger. None of those can be
scripted, and no lawful public corpus of them exists. XMPP is used because the traffic
*shape* it produces — small, sporadic, bidirectional stanzas separated by human-length
pauses — is the shape consumer messaging produces, and through ESP the shape is the only
thing an observer can see.

Any model trained on this class classifies *messaging-shaped traffic*. It has never seen
WhatsApp and must not be described as detecting it.

### `voip` is a synthetic RTP endpoint, not a softphone

The VoIP class emits genuine RFC 3550 RTP at a codec's packetisation interval, but there
is **no SIP signalling and no real codec** — the media payload is generated bytes.

Packet timing and size distribution are faithful, and through an ESP tunnel those are
the only observable properties, so the class is fit for its purpose. The corpus
nonetheless contains **no real calls**, and should not be described as though it does.

Everything else is real protocol: real Postfix and Dovecot for email, real nginx origins
for web and video, real Prosody for messaging, real `tcpreplay` for background traffic.

## 7. Known biases and limitations

These are the reasons a model trained here may not transfer, stated so that a
degradation on field data is understood rather than surprising.

1. **Lab-generated.** All traffic originates in Docker containers on one host. Real
   networks have middleboxes, competing traffic, asymmetric routing and MTU diversity
   that this does not reproduce.
2. **Limited implementation diversity.** Every tunnel is **strongSwan on both ends**.
   Real estates mix Cisco, FortiGate, Juniper and Palo Alto, whose retransmission timing,
   payload ordering and vendor IDs differ. Any implementation-fingerprinting result here
   is therefore about strongSwan and nothing else.
3. **Synthetic think-times.** Web and messaging pauses are drawn from uniform
   distributions. Human timing is not uniform.
4. **Rotating but finite content.** Web pages and video segments rotate between runs to
   avoid memorisation, but the corpus is fixed and incompressible random bytes stand in
   for real media.
5. **Replay distorts timing**, as described in §2.
6. **NAT-T is always present.** Docker's bridge NAT causes IKE to move to UDP 4500, so
   captures here over-represent NAT traversal relative to a site-to-site estate on public
   addresses. This is realistic for remote-access deployments and unrepresentative of
   gateway-to-gateway ones.
7. **IPv6 is defined in the matrix but the topology is IPv4-only.** IPv6 cells cannot
   currently establish; they are recorded as failures rather than silently dropped.
8. **Aggressive Mode required an explicit unlock.** strongSwan refuses IKEv1 Aggressive
   Mode with a PSK unless
   `charon.i_dont_care_about_security_and_use_aggressive_mode_psk` is set — it named the
   option that way deliberately, and it is right to. The testbed image sets it because
   the lab must be able to *build* the insecure configuration in order to capture it and
   prove the analyser detects it. It appears nowhere in anything the remediation
   generators emit.

## 8. Reproducing the corpus

```bash
# What can be fetched automatically; prints instructions for what cannot
python scripts/fetch_external.py

# Prove for yourself that the named corpora contain no IPsec
python scripts/audit_external_datasets.py

# One cell, end to end
python -m testbed.orchestrate.single_run --config-label weak

# Measure the separation between traffic classes
python scripts/generator_shapes.py --duration-s 60
```

The sweep is resumable: state is written after every cell, so an interrupted run
continues rather than restarting, and no cell is ever run twice.
